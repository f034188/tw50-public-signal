## 二、同起始日、同投入日，0050 對照才能比較

假設朋友啟用日資產為 100,000 元，月底再**實際投入** 20,000 元，這不是 20,000 元的策略獲利。比較應當建立兩條帳：

| 日期／資料 | 朋友 F/A 實際或模擬帳 | 0050 買進持有對照 |
|---|---|---|
| 啟用日 | 已確認股數、現金 × 當天可靠市價，形成起始淨值 | 使用相同起始淨值，按當天 0050 價格和費用買進整數股、餘額現金 |
| 薪資投入日 | 確認 20,000 已進入 F/A，單獨記成外部入金；是否買進需另有已確認成交 | 在**相同日期**增加 20,000，以該日有效 0050 收盤價和相同買入費率再買，剩餘現金保留 |
| 外部提領日 | 確認日期和提領金額，不將提領視為虧損 | 以相同日期提領；若現金不足，按有效 0050 收盤價扣交易費賣出足額整數股 |
| 0050 除息／分割 | 如友人持有 0050，依核實的公司行動處理庫存和應收股利 | 用**未調整收盤價＋實際公司行動**處理整數股、應收股息及入帳，不重複計入「含息調整價」 |
| 評估日 | 計算淨資產、淨投入、TWR 及滿一年後可驗證的 XIRR | 同樣計算，並顯示「0050 TWR − F/A TWR」百分點差異 |

**公平性提醒：**若朋友啟用時原本已有庫存，F/A 是從既有資產市值開始、以前的購買成本不一定知道；0050 對照則在同日起算並計入初始新買入成本。這兩種情況**不是**完全相同的初始交易成本。提示卡片應保留「起始成本基礎不同」標籤；要做完全對等的新建倉比較，必須兩組都採用相同新建倉成本規則。

同時，這個參考對照需要**每個有效交易日的 0050 官方原始價格，以及當日公司行動清單已核對**。缺一天、無法確認股利或分割，不能宣稱績效已核實。程式本身沒有自動下載整段行情；`benchmark_0050_price_basis=OFFICIAL_RAW_CLOSE` 等欄位是**由上游提供者負責核實的聲明**，不是 Python 自行證明資料來自證交所。

## 三、虛構範例算出什麼？

測資起始 F/A 資產 **24,000 元**；第二天 F、A 各投入 **500 元**；同日兩本帳按虛構成交價買入，第三天價格變動，均為構造測資。

| 指標 | F/A 帳 | 0050 買進持有假設 |
|---|---:|---:|
| 起始資產 | 24,000 元 | 24,000 元 |
| 外部淨入金 | +1,000 元 | +1,000 元 |
| 第三天市值 | **25,213.00 元** | **25,208.53 元** |
| 扣除淨入金後的淨損益 | **+213.00 元** | **+208.53 元** |

**注意：**這些不是兩檔 ETF 曾出現的真實價格序列，也不是投資績效預測；僅用來驗證費率和現金流不被混淆。兩組起始成本不完全對等，差額不能解讀為策略優勢。

## 四、可靠接續，不應靠 ChatGPT 猜庫存

建議朋友的「每次更新」資料分成：

1. **初始已確認快照**：日期、F 與 A 各自 0050／00631L 整數股數、現金，以及同一日期的有效市價。無法分帳時不得把總持股假設分一半。
2. **往後新增紀錄**：有效交易日的官方行情；確認已成交才記 `BUY/SELL`（唯一 ID、實際股數、成交價、費用）；薪資只有本人確認實際可投資金額才記 `DEPOSIT`；內部 F/A 轉移用 `INTERNAL_TRANSFER`，不可重算薪水。
3. **資料品質狀態**：缺價、停牌、分割、除息、應收股利及券商帳戶尚未同步時，顯示「待查／暫估」。**模型應調整 ≠ 本人已成交**。
4. **保存與續接**：本人掌管一份**私人帳本檔**（可以是自有裝置的私人資料夾／私有雲端），每次更新只追加新交易日，原始檔保留備份。使用同一帳本來源生成下一次提醒，不靠 ChatGPT 記憶推測。

### 本機參考命令（適用懂得執行 Python 的朋友）

1. 自己建立**不在 GitHub 專案目錄內**、本人可讀寫且其他人無權讀取的私人資料夾。
2. 首次使用：
   `python tools/friend_private_local_ledger.py init --private-file /自己私人資料夾/account.json --initial-json /私人資料夾/初始帳本.json`
3. 之後：
   `python tools/friend_private_local_ledger.py append --private-file /私人資料夾/account.json --day-json /私人資料夾/當日紀錄.json --expected-sha256 上次成功回傳的ledger_sha256`
4. 不能重複寫入同一天；原本帳本有衝突時先檢查來源與上次成功紀錄，不要直接改動隱藏雜湊或把紀錄刪掉。

這是**本機 JSON 檔，不會加密**。需由本人負責檔案與備份安全；SHA256 是防止意外覆寫／偵測資料遭改動的輔助，而非防止擁有檔案者竄改、也不是身分驗證。程式會拒絕在公開專案目錄儲存個人帳本；本機文件不會自動上傳 GitHub。

**最重要的功能邊界：**目前公開網站只有**非個人化市場訊號**。這份私人本機檔案並**沒有**被朋友的 ChatGPT 每日排程自動讀取。若朋友希望完全自動接續，必須另選本人管理的安全資料儲存機制與具有授權的連接方式並實測；不能因為 GitHub 52 項測試通過就說定時任務可以讀本機私人檔。
